# cc-jsonl-monitor

Claude Code JSONL 기록을 **왼쪽 파일 트리에서 선택하고 오른쪽에서 읽는 뷰어**입니다. Chrome 확장은 서버 없이 폴더·파일을 연결하고, 로컬 서버 버전은 절대 경로 직접 입력을 지원합니다.

## Chrome 확장 설치

확장 사용자는 Node.js나 서버가 필요하지 않습니다. Chrome 데스크톱 122 이상을 대상으로 합니다. 현재는 압축 해제 설치용 빌드이며 웹 스토어에는 아직 게시되지 않았습니다.

개발 환경에서 빌드하려면 Node.js 22.12 이상과 npm이 필요합니다.

```sh
npm ci
npm run build:extension
```

1. Chrome에서 `chrome://extensions`를 열고 **개발자 모드**를 켭니다.
2. **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 저장소의 `dist/extension` 폴더를 선택합니다.
3. 확장 아이콘을 누르면 전용 뷰어 탭이 열립니다.
4. **폴더 연결**에서 Claude 로그가 있는 `.claude/projects` 폴더를 고르거나, **파일 열기**로 JSONL 하나를 선택합니다. Windows 선택창에 폴더 경로를 붙여넣어 이동할 수도 있습니다.
5. 최근 연결은 최대 8개를 기억합니다. 다음 실행에서 읽기 권한이 남아 있으면 가장 최근 연결을 복원하며, 권한이 필요하면 최근 연결을 눌러 다시 허용합니다.
6. **폴더 내 경로**에 `project/session.jsonl`처럼 상대 경로를 입력해 바로 이동할 수 있습니다. 브라우저는 원래 절대 경로를 제공하지 않으므로 연결한 폴더 이름과 내부 경로로 표시합니다.

최근 연결의 ×는 저장된 연결과 활성 화면을 지우며 원본 파일은 삭제하지 않습니다. 브라우저 권한 자체의 해제는 Chrome에서 관리합니다. 탭을 닫으면 감시와 메모리 캐시가 종료됩니다.

Windows에서 ZIP을 만들려면 `npm run package:extension`을 실행합니다. 결과는 `dist/release/cc-jsonl-monitor-extension.zip`입니다. 다른 OS에서는 `dist/extension` 내부 파일을 ZIP 루트에 넣어 압축하면 됩니다. ZIP은 확장 실행에 필요한 파일만 포함합니다.

## 조회 기능

- **기록 제목**에서 사용자 요청·Claude·도구 호출·도구 결과·생각 기록·시스템·미지원 기록을 각각 켜고 끕니다. 여러 제목 선택은 OR 조건이며 검색·세션·기간·오류 필터와는 AND 조건입니다. 숫자는 파일 전체의 제목별 개수입니다.
- **전체 / 선택 해제**로 한 번에 조절합니다. 하나도 선택하지 않으면 0개가 표시됩니다. **오류만**으로 실패 기록을 추가로 좁힐 수 있습니다.
- 오른쪽 위 **화면 테마**에서 시스템·밝게·어둡게를 선택합니다. 기본은 시스템 설정이며 선택값은 브라우저에 저장됩니다.
- 파일 검색, 세션·날짜 필터, 과거/최신 정렬, 내 시간대/UTC 표시를 지원합니다.
- **원문**은 해당 JSONL 줄을 펼칩니다. 버전이 달라졌으면 새로고침 후 확인하도록 안내합니다.
- **변경 확인**이 켜져 있으면 약 2.5초마다 현재 파일을 확인합니다. **다시 읽기**를 눌러 반영하며, 읽던 화면을 강제로 바꾸지 않습니다.
- 폴더 선택 시 하위 폴더·JSONL 목록을 표시합니다. 파일 트리는 방향키 탐색과 접기를 지원합니다.
- BOM·CRLF·여러 content 블록·시각 누락·깨진 줄·미완성 마지막 줄을 처리하고, 세션과 호출 ID가 명확할 때 도구 호출과 결과를 연결합니다.

기록에 없는 정보를 추정하지 않습니다. 프로젝트 폴더명을 원래 경로로 역변환하지 않고 메타데이터의 `cwd`를 표시합니다. 세션 ID가 없으면 임의로 만들지 않습니다. `user` 역할의 도구 결과를 사용자 요청으로 집계하지 않으며, 마지막 기록 시각은 작업 완료 시각이 아닙니다.

## 로컬 서버 실행

```sh
npm ci
npm run build
npm start
```

브라우저에서 [로컬 뷰어](http://127.0.0.1:4317)를 엽니다. 사용하는 동안 서버를 실행하며 종료는 서버 터미널에서 `Ctrl+C`를 누릅니다. 개발 중에는 `npm run dev`를 사용합니다.

상단 **기준 경로**에 폴더 또는 JSONL의 절대 경로를 입력하고 **경로 열기**를 누릅니다. 공백·한글·따옴표로 감싼 경로를 지원합니다. **기본 로그 폴더**는 `CLAUDE_CONFIG_DIR/projects` 또는 사용자 홈의 `.claude/projects`입니다.

**샘플로 살펴보기**로 `samples/`의 가상 JSONL을 읽을 수 있습니다. 단일 파일을 열면 주변 폴더에는 접근하지 않습니다. 포트를 바꾸려면 PowerShell에서 `$env:PORT = '4318'`을 지정한 후 실행합니다.

## 현재 한계

| 항목 | 동작 |
| --- | --- |
| 입력 | 확장: 폴더/파일 선택창, 연결 폴더 내 상대 경로. 서버: 절대 경로 입력 |
| 탐색 | 하위 항목 지연 읽기, 폴더당 2,000개까지 표시 |
| 검색 | 선택 파일의 이벤트별 앞 8,000자와 도구명·호출 ID·세션 ID·cwd |
| 처리 제한 | 파일 128 MiB, 한 줄 512 KiB, 50,000 이벤트, 미리보기 합계 16,777,216자 |
| 갱신 | 변경 시 파일 전체를 스트림으로 다시 파싱. 증분 인덱스 없음 |
| 캐시 | 메모리 최근 3파일, 최대 동시 파싱 4개 |
| 연결 | 확장: 최근 8개 저장, 활성 연결 1개. 서버: 실행 동안 최대 32개 |
| 원문 | JSON 들여쓰기, 줄바꿈/BOM 정규화. 원본 바이트는 수정하지 않음 |
| 호환성 | 합성 데이터로 검증. Claude Code 모든 내부 버전 호환을 보장하지 않음 |
| 성능 | 제안서의 10만 이벤트·200 MB 목표는 미검증이며 현재 처리 한도 밖 |

확장의 변경 확인은 파일 크기와 수정 시각을 비교합니다. 동일 크기·동일 수정 시각으로 덮어쓴 파일은 자동 감지되지 않을 수 있으며, **새로고침**을 누르면 캐시를 버리고 다시 읽습니다. 백그라운드 탭의 타이머는 Chrome이 늦출 수 있으며, 탭이 다시 활성화되면 변경을 확인합니다. 탭 종료 후 상시 감시와 임의 절대 경로 자동 접근은 제공하지 않습니다.

## 데이터 취급

확장은 외부 통신·웹사이트 접근 권한을 요청하지 않습니다. 선택한 폴더·파일을 읽기 전용으로 사용하고, 파싱·검색은 전용 Web Worker에서 처리합니다. 최근 연결 핸들·이름·종류·사용 시각과 테마를 저장하며 로그 본문은 영구 저장소나 동기화 저장소에 복사하지 않습니다. [개인정보 처리 안내](docs/extension/privacy.md)를 참고하세요.

서버 버전은 `127.0.0.1`에만 바인딩합니다. 등록 루트 밖의 탐색과 외부로 연결된 링크를 차단합니다. Host/Origin 및 앱 요청 헤더를 검사하고 CORS를 허용하지 않습니다.

두 버전 모두 원본 파일을 수정·삭제하거나 로그를 외부 서비스로 전송하지 않습니다. 기록의 HTML·이미지·명령을 실행하지 않습니다. 민감 값 가림은 알려진 일부 패턴에 대한 표시 보조 기능이며 모든 민감 정보 탐지를 보장하지 않습니다.

## 검증

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run build:extension
npm run test:extension
```

`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 설치된 Chromium 실행 파일을 지정할 수 있습니다. 서버 테스트는 파서·필터·경로 경계·파일 변경을, 브라우저 테스트는 탐색·검색·원문·테마·반응형 화면을 확인합니다. 실제 사용자 대화를 fixture로 넣지 않습니다.

확장 테스트는 실제 빌드 패키지와 FileSystemHandle·IndexedDB·Worker를 사용합니다. 운영체제 선택창만 합성 OPFS 폴더 핸들로 대체합니다. 네이티브 선택창과 브라우저 재시작에 따른 권한 정책은 데스크톱 제어 연결 오류로 직접 검증하지 못했습니다. [배포 및 수동 검증 안내](docs/extension/release.md)에 남은 항목을 기록했습니다.

## 구조

```text
src/                 React 화면, 테마
src/browser/         확장 파일 접근, 연결 저장, 분석 Worker
extension/           Manifest V3, 아이콘, 탭 열기
server/              로컬 HTTP API, 경로 권한, 스트림 읽기
shared/              공용 파서·필터·데이터 계약
samples/             가상 JSONL 샘플
tests/               단위 테스트 및 서버/확장 브라우저 테스트
docs/extension/      개인정보 처리 안내와 배포 검증
docs/proposal/       최초 제안서
dist/                빌드 결과와 설치 ZIP (Git 제외)
```

[최초 제안서](docs/proposal/README.md)의 3영역 화면은 초기 구상이며, 실제 구현에는 이후 확정된 **좌측 파일 트리 / 우측 선택 내용** 구조를 적용했습니다.
