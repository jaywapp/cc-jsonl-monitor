# cc-jsonl-monitor

Claude Code JSONL 기록을 **왼쪽 파일 트리에서 선택하고 오른쪽에서 읽는 로컬 뷰어**입니다. 기준 폴더 또는 개별 JSONL 파일의 절대 경로를 직접 입력할 수 있습니다.

## 실행

Node.js 22.12 이상과 npm이 필요합니다. Windows에서 검증했습니다.

```sh
npm ci
npm run build
npm start
```

브라우저에서 **http://127.0.0.1:4317** 을 엽니다. 앱을 사용하는 동안 서버를 실행해 둡니다. 종료는 서버 터미널에서 `Ctrl+C`를 누릅니다. `index.html`을 더블클릭하는 방식으로 실행하는 앱이 아닙니다.

개발 중에는 다음 명령으로 화면 변경을 바로 반영할 수 있습니다.

```sh
npm run dev
```

기본 포트를 바꾸려면 `PORT` 환경 변수를 지정합니다. PowerShell 예시:

```powershell
$env:PORT = '4318'
npm start
```

## 사용 방법

1. 상단 **기준 경로**에 로그 폴더 또는 `.jsonl` 파일의 절대 경로를 입력하고 **경로 열기**를 누릅니다. 공백·한글이 있는 경로와 따옴표로 감싼 경로도 처리합니다.
2. **기본 로그 폴더**는 `CLAUDE_CONFIG_DIR/projects`, 해당 환경 변수가 없으면 사용자 홈의 `.claude/projects`를 엽니다. 설정에 따라 실제 위치가 다르면 직접 경로를 입력합니다.
3. 왼쪽에서 폴더를 펼칩니다. 폴더를 선택하면 오른쪽에 하위 폴더·JSONL 목록, 파일을 선택하면 해당 기록이 표시됩니다.
4. 파일 화면에서 검색, 종류·세션·날짜 필터, 시간 정렬을 사용합니다. 시간대는 내 컴퓨터 시간대 또는 UTC를 선택할 수 있습니다.
5. **원문**을 펼치면 해당 파일의 줄을 읽습니다. 파일이 변경되어 줄 위치의 신뢰성이 달라지면 새로고침을 안내합니다.
6. **변경 확인**이 켜져 있으면 약 2.5초마다 현재 파일의 변경 여부를 확인합니다. 변경 안내에서 **다시 읽기**를 눌러 반영합니다. 과거를 읽고 있는 동안 기록을 강제로 교체하거나 스크롤하지 않습니다.

처음에는 **샘플로 살펴보기**를 눌러 확인할 수 있습니다. `samples/`는 가상 데이터를 넣은 실제 JSONL 파일입니다. 기본 로그 폴더 밖의 파일 하나를 열면 해당 파일만 허용하며 주변 폴더는 자동으로 읽지 않습니다.

## 구현된 기능

- 기준 경로의 실제 폴더 계층을 유지하는 파일 트리와 2분할 레이아웃
- 폴더·개별 JSONL 직접 경로 입력, 하위 폴더 선택, 파일 목록 새로고침
- 사용자 요청, Claude 응답, 도구 호출·결과, 생각 기록, 시스템, 미지원 레코드 구분
- 같은 파일·세션의 호출 ID가 유일한 경우 도구 호출과 결과 연결, 미관측·모호한 연결 표시
- 파일 내 검색, 이벤트 종류·오류·세션·날짜 필터, 과거/최신순 정렬
- 원문 줄 펼치기와 인식 가능한 민감 값 가림, 긴 메시지 접기
- BOM·CRLF·여러 content 블록·시각 누락·깨진 줄·미완성 마지막 줄 처리
- 파일 변경·교체·축소·삭제 감지, 페이지당 100개 기록 표시
- 좁은 화면에서 탐색기/내용을 세로 배치, 탐색기 접기, 키보드 방향키 탐색

기록에 없는 정보를 추정하지 않습니다. 프로젝트 폴더명을 원래 경로로 역변환하지 않고 메타데이터의 `cwd`를 표시합니다. 세션 ID가 없으면 임의로 만들어 사람이나 세션을 추론하지 않습니다. `user` 역할에 들어 있는 도구 결과를 사용자 요청으로 집계하지 않습니다. 마지막 기록 시각은 작업 완료 시각이 아닙니다.

## 현재 버전의 한계

이 버전은 파일 트리 중심의 첫 구현입니다. 제안서의 모든 후속 기능이나 성능 목표를 달성했다는 의미는 아닙니다.

| 항목 | 현재 동작 |
| --- | --- |
| 입력 방식 | 절대 경로 직접 입력. 운영체제의 네이티브 폴더/파일 선택기는 아직 없음 |
| 탐색 범위 | 폴더의 바로 아래 항목을 필요할 때 읽음. 한 폴더당 최대 2,000개, 초과 시 안내 |
| 검색 범위 | 선택한 파일의 이벤트별 앞 8,000자 미리보기와 도구명·호출 ID·세션 ID·cwd. 전체 프로젝트 검색은 아직 없음 |
| 처리 제한 | 파일 128 MiB, 한 줄 512 KiB, 최대 50,000 이벤트, 미리보기 합계 16,777,216자. 초과하면 명시적 오류 |
| 기록 갱신 | 변경된 파일은 전체 스트림을 다시 파싱. byte 증분 인덱스와 SQLite는 아직 사용하지 않음 |
| 캐시 | 메모리에서 최근 3파일 유지. 최대 동시 파싱 4개. 서버 재시작 시 없어짐 |
| 등록 경로 | 서버 실행 동안 최대 32개. 최근 경로를 디스크에 저장하지 않음 |
| 원문 | JSON은 읽기 좋게 들여쓰기. 줄바꿈/BOM 표현은 정규화되며 파일 바이트 자체는 수정하지 않음 |
| JSONL 호환성 | 공개된 예시 구조와 비식별 테스트 데이터로 검증. Claude Code의 모든 내부 버전을 보장하지 않음 |
| 성능 | 기능 테스트 완료. 제안서의 10만 이벤트·200 MB 벤치마크 목표는 미검증이며 현재 파일/이벤트 한도 밖 |

생각/도구/미지원 콘텐츠도 기록에 있는 내용만 표시합니다. 이미지나 도구 명령은 실행하지 않습니다. 실제 로그가 한도에 걸리면 한도를 무조건 높이기보다 스트리밍 인덱스와 원문 지연 조회를 확장하는 것이 다음 단계입니다.

## 데이터 취급

서버는 `127.0.0.1`에만 바인딩합니다. 등록한 경로 밖의 탐색과 외부 루트로 나가는 링크를 차단하며, 단일 파일과 폴더의 읽기 권한을 구분합니다. Host/Origin 및 앱 요청 헤더를 검사하고 CORS를 허용하지 않습니다.

원본 파일을 수정·삭제하지 않으며, 대화 내용을 외부 서비스로 전송하거나 디스크 인덱스로 복사하지 않습니다. 브라우저에는 텍스트로 표시하고 원격 이미지나 HTML을 실행하지 않습니다. 민감 값 가림은 알려진 일부 패턴에 대한 표시 보조 기능으로, 모든 키·개인정보 탐지를 보장하지 않습니다. 서버와 브라우저 메모리에는 선택한 원문이 존재합니다.

## 검증

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

브라우저 검증은 빌드 결과를 사용합니다. 기본 포트에서 앱이 실행 중이면 재사용하고, 아니면 테스트 도구가 서버를 시작합니다. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 환경 변수로 이미 설치된 Chromium 실행 파일을 지정할 수도 있습니다.

서버 테스트는 파싱, 잘못된 행 격리, 도구 연결, 날짜/정렬, 경로 접근 경계, 파일 변경 및 원문 버전 검증을 다룹니다. 브라우저 테스트는 실제 임시 JSONL로 트리 선택, 직접 경로, 검색·필터·정렬, 원문, 변경 반영, 원본 보존, 모바일/200% 확대를 확인합니다. 테스트 데이터와 화면 캡처는 Git에서 제외되는 `.local/`에 저장합니다. 실제 사용자 대화를 테스트 fixture로 넣지 않습니다.

## 프로젝트 구조

```text
src/                 React 파일 탐색·기록 화면
server/              로컬 HTTP API, 경로 권한, JSONL 파서
shared/types.ts      화면/서버 데이터 계약
samples/             가상 JSONL 샘플
tests/               서버 테스트와 브라우저 시나리오
docs/proposal/       최초 제안서와 가상 화면 예시
dist/                빌드 결과 (Git 제외)
```

최초 제안서는 [docs/proposal/README.md](docs/proposal/README.md)에서 확인할 수 있습니다. 제안 당시 3영역 화면은 초기 구상이며, 실제 구현에는 이후 확정된 **좌측 파일 트리 / 우측 선택 내용** 구조를 적용했습니다.
