# cc-jsonl-monitor 제안서

Claude Code의 프로젝트별 JSONL 기록에서 **어느 워크스페이스에서, 어떤 세션으로, 어떤 요청과 실행을 거쳤는지** 읽는 로컬 전용 뷰어를 제안한다.

- 작성일: 2026-09-15
- 상태: 검토용 제안. 제품 구현과 성능 검증 이전이다.
- 저장소: [jaywapp/cc-jsonl-monitor](https://github.com/jaywapp/cc-jsonl-monitor)
- 웹 제안서: [index.html](./index.html)을 브라우저에서 연다. 설치와 빌드가 필요 없다.
- 화면 예시: 워크스페이스·세션 선택, 내용 검색, 이벤트 필터, 정렬, 원문 펼치기를 지원한다. 모든 데이터는 가상이며 실제 로그를 읽지 않는다.

## 1. 해결할 문제

JSONL은 저장과 처리에 적합하지만 사람이 작업을 복기하기에는 어렵다. 파일 이름만으로 작업 목적을 알기 어렵고, 사용자 메시지 사이에 도구 실행·결과·시스템 기록이 섞인다. 여러 프로젝트와 재개된 세션을 오가면 앞뒤 맥락을 찾는 비용이 커진다.

제품의 성공 기준은 로그를 많이 표시하는 것이 아니라, 사용자가 특정 작업의 **요청 → 조사 → 변경 시도 → 검증 → 응답**을 원문 근거와 함께 이해하는 것이다. 이 단계는 설명용이며 모든 세션이 같은 단계를 거친다고 가정하지 않는다.

## 2. 대상 사용자와 범위

1차 대상은 자기 PC에서 Claude Code CLI를 사용하는 개발자로 가정한다. 자신의 이전 작업을 찾거나, 실패 후 재시도 과정을 복기하거나, 여러 프로젝트 사이의 작업 전환을 확인한다.

여기서 '사용자'는 가져온 로컬 데이터 소유자다. JSONL의 `user` 역할은 메시지 역할이지 사람의 계정 ID가 아니다. 도구 결과도 user 메시지에 실릴 수 있으므로 모든 user 항목을 사람의 요청으로 세지 않는다. 다중 사용자·다중 장치가 필요해지면 사용자가 지정하는 데이터 소스 이름으로 구분하고, 경로나 프롬프트로 신원을 추론하지 않는다.

이번 산출물은 제안서와 가상 화면 예시다. 실제 수집기·뷰어 앱, GitHub 업로드, 배포는 포함하지 않는다.

## 3. 핵심 사용 시나리오

| 상황 | 사용 동선 | 확인할 결과 |
| --- | --- | --- |
| 어제 어떤 수정을 요청했는가? | 루트 경로 선택 → 날짜로 세션 좁히기 → 첫 요청 확인 | 요청 원문과 이후 응답 |
| 테스트가 실패한 이유는? | 세션 선택 → 오류 필터 → 호출과 결과 펼치기 | 실패 출력, 재시도, 이후 성공 결과 |
| 여러 세션에서 작업이 어떻게 이어졌는가? | 워크스페이스 → 최근 활동순 세션 → 각 세션 타임라인 | 세션 경계를 보존한 작업 이력 |
| 기억나는 파일명으로 찾고 싶다 | 워크스페이스 검색 → 일치 세션 → 일치 이벤트로 이동 | 파일 경로가 나온 실제 메시지 |
| 지금 쌓이는 기록을 보고 싶다 | 세션 선택 → 새 기록 알림 → 최신 위치로 이동 | 읽던 위치를 유지하는 증분 갱신 |

## 4. 정보 구조와 화면

탐색 계층은 **데이터 소스 → 워크스페이스 루트 → 세션 → 이벤트**다. 기본 화면은 왼쪽 워크스페이스 목록, 가운데 세션 목록, 오른쪽 타임라인의 3영역으로 제안한다. 작은 화면에서는 위에서 아래로 쌓고 현재 선택을 유지한다.

- **워크스페이스:** 별칭, 전체 루트 경로, 세션 수, 마지막 기록 시각. 같은 폴더명도 전체 경로가 다르면 별개다. Git 저장소 루트와 실행 당시 `cwd`는 별도 정보다.
- **세션:** 기존 이름이 있으면 사용하고, 없으면 첫 번째 사람 요청을 잘라 표시한다. 모델을 호출해 제목을 생성하지 않는다. ID·첫/마지막 기록·관측된 경과 시간·오류 수를 제공한다.
- **타임라인:** 기본은 과거 → 최신. 요청, 응답, 도구 호출/결과, 시스템, 알 수 없는 기록을 구분한다. 명령어·파일 경로·실패 메시지는 가까이 표시하고 긴 출력과 원문은 접는다.
- **검색:** 범위를 항상 표시한다. MVP는 선택한 워크스페이스의 세션 제목·프롬프트·응답·도구명·파일 경로·출력에서 텍스트 검색한다. 결과에서 이벤트로 이동할 때 세션·시각을 함께 보여준다.
- **필터:** 기간, 이벤트 종류, 오류 여부. 필터 적용 중 전체/표시 건수를 제공하고 결과가 없으면 초기화 동선을 제공한다.
- **갱신:** 파일이 바뀌면 새 이벤트 개수만 알린다. 사용자가 과거를 읽고 있으면 강제로 스크롤하지 않는다. 현재 상태를 확정할 근거가 없으면 '마지막 기록'으로 표시하며 '실행 중/완료'를 추정하지 않는다.

웹 예시는 범위를 줄여 **선택한 세션 안에서 검색**하며 이를 입력창에 명시한다. 기간 필터와 전체 워크스페이스 검색은 제품 제안에 포함되지만 이번 예시에는 구현하지 않는다.


### 폴더와 파일 경로 직접 지정 (MVP 필수)

기본 폴더 자동 탐색과 함께 **로그 폴더 경로 입력**, **개별 `.jsonl` 파일 절대 경로 입력**, **폴더/파일 선택기**를 제공한다. 기본 저장 위치 밖의 백업·복사본도 읽을 수 있어야 한다. 단일 파일을 열었다고 주변 폴더 전체를 자동 수집하지 않는다. 원래 워크스페이스를 찾을 수 없어도 파일 자체를 열고 '경로 미확인' 상태로 탐색할 수 있어야 한다.

입력은 공백과 감싼 따옴표를 정리한 뒤 경로로만 처리한다. 셸 명령으로 해석하지 않으며 와일드카드와 명령 치환을 지원하지 않는다. 존재 여부 → 파일/폴더 구분 → 읽기 권한 → 확장자와 JSONL 내용의 기본 검증 순서로 검사한다. 상위 폴더 권한을 임의 확대하지 않고 심볼릭 링크 경계도 확인한다. OS별 절대 경로 문법을 검증하고 상대 경로는 기준이 모호하므로 MVP에서 거절한다.

빈 입력은 입력 요청, 잘못된/없는 경로는 수정·다시 선택, 권한 거부는 권한 안내·다른 파일 선택, 미지원 형식은 JSONL 선택 안내를 표시한다. 빈 JSONL은 '아직 기록 없음', 일부 손상된 파일은 정상 줄과 진단을 표시한다. 단일 파일 계속 읽기는 명시적으로 켤 수 있도록 제안한다. 최근 경로는 로컬 설정에만 기억하고 목록 삭제를 제공한다.

웹 예시의 경로 입력은 가상 파일에 해당하는 세션만 열며 실제 파일에 접근하지 않는다.
## 5. 확인한 데이터 특성과 설계 원칙

공식 문서 기준 기본 저장 위치는 `~/.claude/projects/<project>/<session-id>.jsonl`이다. Windows에서는 `%USERPROFILE%\.claude\projects`에 해당한다. 저장 위치는 설정으로 바뀔 수 있고 파일 내부 형식도 버전별로 달라질 수 있다. 따라서 기본 경로는 탐색 제안값으로만 쓰며 직접 데이터 폴더를 고를 수 있어야 한다. [공식 세션 문서](https://code.claude.com/docs/en/sessions#where-transcripts-are-stored)

공식 Agent SDK에는 세션 목록과 메시지를 읽는 함수가 있다. 구현 초기에 SDK의 읽기 API가 필요한 메타데이터와 원문 추적을 충분히 제공하는지 비교한다. 부족한 부분만 별도의 JSONL 어댑터로 처리한다. [공식 SDK 세션 문서](https://code.claude.com/docs/en/agent-sdk/sessions)

공식 hooks 입력은 세션 ID·`cwd`·transcript 경로를 제공하며 서브에이전트 기록은 별도 경로가 될 수 있다. 기존 기록 조회에는 hook 설치를 요구하지 않는다. 이 문서의 내부 필드 후보는 고정 계약이 아니며 실제 지원 버전의 비식별 fixture로 검증해야 한다. [공식 hooks 문서](https://code.claude.com/docs/en/hooks)

### 워크스페이스 식별

인코딩된 프로젝트 폴더명의 하이픈을 슬래시로 치환해 원래 경로를 복원하지 않는다. 손실된 문자·긴 경로·사용자 정의 폴더명 때문에 오인할 수 있다.

우선순위는 검증된 세션 메타데이터의 실제 경로 → 이벤트의 `cwd` → 사용자 매핑이다. 알 수 없으면 '경로 미확인'으로 남긴다. 기본 그룹은 실행 경로이며, 하위 폴더를 하나의 워크스페이스 루트로 묶는 것은 명시적인 매핑으로 제안한다. 표시용 원래 경로와 식별용 정규화 경로를 함께 보존한다. 대소문자 규칙은 원본 파일시스템에 맞추고 심볼릭 링크·worktree를 임의 합치지 않는다. 세션 도중 경로가 바뀌면 이벤트별 경로를 유지한다.

### 세션과 시간

세션의 논리 키는 데이터 소스 ID와 session ID의 조합이다. 같은 ID가 여러 파일에 있으면 출처를 보존한 뒤 중복 복사인지, 이동된 세션 조각인지 판별한다. 확인되지 않은 중복은 합치지 않고 경고한다. 분기된 다른 ID의 세션은 별도로 표시한다.

시각은 원래 시간대와 UTC 값을 보존하고 UI에는 선택한 시간대를 표시한다. 동일 시각은 파일 식별자·줄 번호·블록 순서로 안정적으로 정렬한다. 시각이 없거나 잘못된 이벤트는 임의 시각을 만들지 않고 '시각 미상' 그룹에 원본 순서로 둔다. 시각순 화면과 부모 관계에 따른 대화 순서가 다를 수 있으므로 부모 연결을 보조 정보로 유지한다. 첫/마지막 이벤트의 차이는 관측 구간이지 실제 노동 시간이나 모델 실행 시간이 아니다.

### 사람이 읽을 수 있는 이벤트

메시지 역할과 content 블록을 함께 본다. 문자열·텍스트 배열·도구 호출·도구 결과를 구분하고 하나의 JSONL 줄에 여러 블록이 있으면 각각 표시하되 같은 원본 위치를 가리킨다. `tool_use`와 `tool_result`는 해당 버전에서 검증한 호출 ID로 연결한다. 인접한 줄이라는 이유로 연결하지 않는다. 결과가 없는 호출은 '결과 미관측', 호출이 없는 결과는 '호출 미확인'이다.

생각·압축 요약·시스템 이벤트는 접어서 표시하며, 기록에 없는 사고 과정은 생성하지 않는다. 하위 에이전트는 독립 주체로 표기하고 부모 관계가 확인되는 경우만 연결한다. 수정 도구 성공은 파일 변경 시도의 기록이며 최종 디스크 상태나 커밋 완료를 증명하지 않는다. 오류 이후 정상 결과도 세션 전체 성공을 뜻하지 않는다.

## 6. 제안 아키텍처

실제 제품은 **로컬 수집 프로세스 + 브라우저 UI**로 먼저 구현하는 안을 권고한다. 일반 정적 웹 페이지가 사용자 동의 없이 임의 로컬 경로를 지속 감시할 수 있다고 전제하지 않는다. 기술 스택은 확정하지 않았으며, TypeScript 기반 로컬 서비스·React UI·SQLite 검색 인덱스를 검토 후보로 둔다.

```text
사용자가 선택한 로그 폴더 (읽기 전용)
  → 파일 탐색 / 변화 감지
  → SDK 읽기 API 또는 버전별 JSONL 어댑터
  → 정규화 / 연결 / 중복 판별
  → 재생성 가능한 로컬 인덱스
  → localhost API + 갱신 알림
  → 워크스페이스 / 세션 / 타임라인 UI
```

| 후보 | 이점 | 제약 / 선택 근거 |
| --- | --- | --- |
| 정적 웹 + 파일 가져오기 | 설치 없이 명시적으로 선택한 파일 열기 | 자동 탐색·상시 감시에 한계. 일회성 뷰어에는 가능 |
| 로컬 서비스 + 웹 UI | 파일 감시·검색과 화면을 분리하기 쉬움 | 로컬 프로세스 실행과 배포 패키지 필요. MVP 권고안 |
| 데스크톱 앱 | 폴더 선택·트레이·자동 시작을 통합 | 패키징/서명/업데이트 부담. MVP 이후 검토 |

로컬 서비스는 loopback에만 바인딩하고 Host/Origin 검사, 허용한 경로 목록, 임의 파일 조회 방지를 적용한다. 네트워크 공유 서비스로 열지 않는다. 인덱스도 민감한 대화의 사본이므로 사용자 전용 저장소에 두고 재생성·삭제 기능을 제공한다. 원본 로그는 수정하거나 삭제하지 않는다.

### 최소 데이터 모델 제안

| 개체 | 필수 데이터 / 관계 |
| --- | --- |
| Source | 내부 ID, 사용자가 붙인 이름, 선택한 로그 루트, 어댑터 버전 |
| Workspace | 내부 ID, 원래 경로, 정규화 경로, 매핑 근거, 경로 확인 상태 |
| Session | source ID + session ID, 제목 및 출처, workspace 관계, 첫/마지막 기록 |
| Event | 내부 ID, 원본 uuid(있을 때), 역할/종류, 시각, cwd, 블록, 부모/도구 연결 |
| Provenance | source file ID, 파일 세대, 줄 번호, byte 범위, block 순서, 내용 지문 |
| Diagnostic | 파일·줄·에러 종류·재시도 상태. 대화 내용과 시크릿은 진단 로그에 복사하지 않음 |

원본을 권위 있는 데이터로 유지하고 인덱스에는 탐색에 필요한 값만 저장한다. 원문 열기는 byte 위치로 읽되 파일 세대/지문이 다르면 재색인한다. 원본 삭제 시 기본 정책은 해당 검색 인덱스도 정리하며 자동 영구 보관 기능은 제공하지 않는다.

### 큰 파일과 예외 처리

- 초기 스캔은 점진적으로 진행하고 진행 건수·읽기 실패 건수를 표시한다. 전체 파일을 한 번에 메모리에 올리지 않는다.
- 완료된 줄만 커밋한다. 마지막 줄이 쓰이는 중이면 byte 조각을 보관하고 다음 변경에서 재시도한다. UTF-8 다중 바이트 문자가 나뉘어도 보존한다.
- 중간의 잘못된 JSON은 줄 단위로 격리하고 정상 기록 탐색은 계속한다. 미지원 종류는 '알 수 없는 이벤트'로 원문 접근을 제공한다.
- 크기 감소, 동일 크기 덮어쓰기, 파일 교체, 재개·압축·중복 기록을 고려한다. 파일 세대와 지문으로 커서를 무효화하고 재색인한다. append-only로 단정하지 않는다.
- 파일 감시 누락을 대비해 수동 새로고침과 저빈도 정합성 스캔을 둔다. 읽기 잠금·권한 오류는 재시도 또는 폴더 변경을 안내한다.
- 동일 원본 이벤트의 재수집은 멱등 처리한다. UUID가 없으면 파일 세대·byte 위치·블록 번호를 키로 쓰되 파일 간 전역 중복 제거는 임의로 하지 않는다.
- 긴 출력은 지연 로딩하고 긴 목록은 가상 스크롤한다. 큰 단일 줄은 자동 폐기하지 않고 지연 읽기 대상으로 표시한다.

## 7. 데이터 보호

MVP는 대화·코드·경로를 외부 서버로 전송하지 않고, 분석용 원격 계측이나 LLM 요약을 기본 기능으로 넣지 않는다. 로그의 명령어를 실행하지 않는다. 텍스트는 HTML로 실행되지 않도록 이스케이프하고 원격 이미지 자동 로드를 막는다. 인식 가능한 토큰과 키는 기본 가림 처리하되 탐지의 완전성을 주장하지 않는다. 원문 보기 전 민감 정보 가능성을 알린다.

내보내기는 초기 범위에서 제외한다. 이후 제공한다면 미리보기와 가림 상태를 사용자가 확인해야 한다. 이번 웹 제안서는 외부 라이브러리·폰트·분석기를 요청하지 않으며 제공된 공식 링크를 사용자가 누를 때만 외부 사이트로 이동한다.

## 8. 개발 범위와 순서

| 단계 | 구현 내용 | 종료 기준 |
| --- | --- | --- |
| 호환성 조사 | 비식별 샘플 수집, 지원 버전 명시, SDK/직접 파싱 비교, 경로 매핑 | 지원·미지원 이벤트 표와 재현 fixture 확보 |
| MVP: 탐색 | 폴더·파일 경로 직접 입력/선택, 루트 분류, 세션 목록, 시간순 뷰, 원문 연결 | 한 작업을 첫 요청부터 결과까지 원문으로 추적 |
| MVP: 탐색 강화 | 검색·필터, 호출/결과 연결, 오류/미상 상태 | 검색 결과가 정확한 세션·이벤트로 이동 |
| MVP: 안정화 | 증분 갱신, 재색인, 큰 파일, 접근성, 로컬 패키지 | 아래 수용 기준을 자동/수동 검증 |
| 후속 | 세션 간 통합 타임라인, 서브에이전트 트리, 북마크, 선택적 내보내기 | MVP 사용 피드백 후 별도 범위 결정 |

MVP에서는 서브에이전트 기록의 존재와 확인된 연결을 보존하되 전용 트리 탐색은 후속으로 둔다. 비용 대시보드, 자동 AI 요약, 실행/재개 제어, 팀별 생산성 비교, 클라우드 동기화는 제외한다. 인력과 샘플 규모가 미정이므로 달력 일정은 산정하지 않는다.

## 9. 수용 기준

| 항목 | 검증 방법 / 통과 조건 |
| --- | --- |
| 직접 경로 지정 | 기본 경로 밖의 단일 JSONL을 절대 경로로 열기. 공백·한글 경로 처리. 빈 값·상대 경로·없는 경로·권한 없음·다른 형식에 복구 안내 |
| 핵심 탐색 | 다른 루트의 동명 폴더가 섞이지 않고 루트 → 세션 → 원문 이벤트로 이동 |
| 시간 정확성 | UTC/로컬 변환, 자정 경계, 동일 시각, 누락 시각 fixture에서 일관된 결과 |
| 메시지 구분 | 도구 결과를 사람 요청으로 오인하지 않고 호출 ID가 일치하는 결과만 연결 |
| 데이터 내성 | 불완전 마지막 줄, 잘못된 중간 줄, 미지원 타입으로 전체 화면이 중단되지 않음 |
| 증분 정확성 | 재시작·파일 교체·중복 알림 이후 누락/중복이 없고 원문 위치가 맞음 |
| 접근성 | 키보드만으로 선택·검색·원문 보기 가능, 200% 확대·좁은 화면에서 탐색 가능 |
| 원본 보호 | 읽기 전후 원본 지문 동일, 가상 명령 실행 없음, 외부 로그 전송 없음 |
| 성능 목표 | 10만 이벤트/총 200 MB fixture에서 최초 색인 30초 이내, 색인 후 목록·검색 p95 500 ms 이내, 완결 줄 반영 2초 이내 |

성능 수치는 측정 결과가 아닌 검증 목표다. Windows 11, SSD, 메모리 16 GB 환경을 잠정 기준으로, CPU 모델·Claude Code 버전·콜드/웜 캐시·샘플 분포·최대 단일 줄 크기를 함께 기록한다. 타임라인 첫 화면은 색인 후 1초 이내, 수집 프로세스 메모리는 500 MB 이하를 추가 목표로 한다.

## 10. 구현 전 결정할 사항

현재 제안은 단일 사용자, 로컬 CLI 기록, Windows 우선 검증을 가정한다. 실제 제품 착수 전에 지원 운영체제, 지원 Claude Code 버전, 로그 규모, 하위 폴더/worktree 묶음 규칙, 실행 배포 방식, 기록 보존 정책을 확정한다. 저장소는 조회 당시 빈 비공개 저장소였고 로컬 대상 폴더에도 기존 구현이 없었다. 기존 아키텍처를 전제로 하지 않았다.
