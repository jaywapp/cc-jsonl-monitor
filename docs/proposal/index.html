추정한 맥락과
관측된 사실을 구분합니다.

폴더명을 경로로 역산하지 않습니다.
실제 메타데이터와 사용자의 경로 매핑을 사용합니다. 실행 폴더와 Git 루트, worktree는 자동으로 합치지 않습니다.
도구 결과는 사람의 요청이 아닙니다.
역할과 메시지 블록을 함께 읽고, 호출 ID가 확인된 결과만 연결합니다. 인접한 기록만으로 관계를 단정하지 않습니다.
기록의 끝이 작업 완료는 아닙니다.
마지막 기록 시각을 보여줍니다. 관측 구간을 실제 작업 시간으로 표현하거나 성공을 추정하지 않습니다.
원문을 언제든 확인할 수 있습니다.
파일·줄·블록 위치를 보존합니다. 누락된 시각이나 미지원 이벤트는 숨기지 않고 확인이 필요한 상태로 표시합니다.

로컬에서 읽고, 브라우저로 봅니다.

실제 제품은 로컬 수집 프로세스와 웹 화면을 분리하는 안을 권고합니다. 정적 페이지가 임의의 로컬 파일을 자동으로 읽고 감시한다고 전제하지 않습니다.

  1. 로그 원본지정한 폴더·파일
    읽기 전용
  2. 수집 · 정규화SDK / JSONL 어댑터
    변경·예외 처리
  3. 로컬 인덱스경로 · 세션 · 이벤트
    재생성 가능한 검색 데이터
  4. 탐색 화면localhost 연결
    검색 · 타임라인 · 원문

기술 선택은 검증 후 확정

TypeScript 로컬 서비스, React 화면, SQLite 검색 인덱스를 후보로 둡니다. 공식 SDK의 읽기 기능을 먼저 비교하고, 부족한 메타데이터만 버전별 어댑터로 보완합니다.

원본 보호를 기본값으로

대화와 코드를 외부로 보내지 않습니다. 명령어를 실행하지 않고, 로컬 인덱스도 민감 데이터로 취급합니다. 원문과 원격 이미지를 실행 가능한 콘텐츠로 렌더링하지 않습니다.

큰 파일·깨진 기록·파일 변경은 어떻게 처리하나요?
  • 완결된 줄만 읽고, 아직 쓰는 중인 마지막 줄은 다음 변경에서 다시 읽습니다.
  • 잘못된 JSON은 줄 단위로 격리합니다. 정상 기록과 미지원 기록의 원문은 계속 볼 수 있습니다.
  • 파일 교체·축소·덮어쓰기를 감지하면 다시 색인합니다. 항상 뒤에만 추가된다고 가정하지 않습니다.
  • 타임라인은 가상 스크롤, 긴 출력은 지연 로딩합니다. 새 기록이 와도 읽던 위치를 유지합니다.
  • 삭제된 원본은 상태를 알리고 기본적으로 검색 인덱스에서도 정리합니다.

개발은 데이터 검증부터 시작합니다.

  1. 호환성 확인

    지원 버전과 비식별 샘플을 정하고 SDK와 직접 파싱을 비교합니다.

  2. 핵심 탐색 구현

    직접 경로 입력, 루트 분류, 세션 목록, 시간순 뷰와 원문 연결을 만듭니다.

  3. 검색과 연결 강화

    검색·필터, 도구 결과 연결, 미상·오류 상태를 완성합니다.

  4. 실사용 검증

    증분 갱신, 큰 파일, 접근성, 원본 보호와 실행 패키지를 검증합니다.

이 정도면 첫 버전입니다.

  • 원하는 JSONL 경로를 붙여넣어 열 수 있다.
  • 다른 루트의 동명 프로젝트가 섞이지 않는다.
  • 요청과 실행 결과를 원문까지 추적할 수 있다.
  • 깨진 한 줄 때문에 전체 탐색이 멈추지 않는다.
  • 다시 읽어도 이벤트가 중복되지 않는다.
  • 키보드와 좁은 화면에서도 탐색할 수 있다.

검증 목표, 측정값 아님
10만 이벤트·200 MB 기준, 색인 후 검색 p95 500 ms 이내와 완결 줄 반영 2초 이내를 목표로 검증합니다.
