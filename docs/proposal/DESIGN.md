# 제안서 화면 디자인 기준

## 목적과 모드

Read: 제품 구상과 개발 범위를 이해하기 위한 웹 제안서다. 내부 화면 예시는 Operate 모드로 루트 → 세션 → 이벤트 탐색에 집중한다. 실제 제품 구현과 혼동되지 않도록 가상 데이터임을 입력 영역과 원문에서 명시한다.

## 디자인 방향

개발자가 낮에 문서를 검토하는 상황을 기준으로 밝은 문서와 짙은 글자를 사용한다. 편집 문서의 큰 제목·여백과 실제 선택 가능한 기록 탐색 영역을 결합한다. 공식 디자인 시스템을 흉내 내는 구현이 아닌 자체 정적 문서 스타일이다.

- DESIGN_VARIANCE: 4. 설명의 흐름과 익숙한 문서 구조를 우선한다.
- MOTION_INTENSITY: 1. 앵커 이동만 부드럽게 하며 동작 줄이기 설정을 존중한다.
- VISUAL_DENSITY: 5. 본문은 넉넉하게, 탐색 영역은 세션 간 비교가 가능하게 구성한다.
- `design-taste-frontend`는 문서의 구성·색·여백에 적용한다. 밀도 높은 뷰어 영역은 해당 스킬의 범위 밖이므로 제품 탐색 규칙과 `impeccable`의 Operate 원칙을 적용한다.

## 토큰과 구성

- 배경 `#fafbfc`, 콘텐츠 `#ffffff`, 본문 `#202c36`, 보조 텍스트 `#596773`.
- 강조 `#205c4b`, 선택 배경 `#e8f1ed`. 오류 `#a02c30`는 의미가 있는 오류 상태에만 사용한다.
- 한글 시스템 글꼴을 사용해 별도 네트워크 의존 없이 읽는다. 경로·시각·원문만 고정폭 글꼴로 표시한다.
- 본문 16px, 작은 UI 14px 전후, 출처·시각 12px. 브라우저 확대를 허용한다.
- 문서 최대 너비 1320px. 외곽 컨테이너 12px, 입력/버튼 6px 모서리.
- 장식 이미지·원격 폰트·패키지 의존 없음. 제품 고유의 경로/세션/시간선 자체를 핵심 시각 요소로 사용한다.

## 반응형과 접근성

950px 이하에서 워크스페이스를 상단으로 이동한다. 700px 이하에서는 루트·세션·타임라인을 세로로 쌓는다. 검색 범위는 '이 세션'으로 표시한다. 버튼에 선택 상태를 제공하고 레이블·포커스·본문 건너뛰기 링크를 둔다. 원문은 native details/summary로 펼친다. 로그 콘텐츠는 textContent로만 출력한다.

인쇄에서는 긴 가상 대화를 생략하고 제안 본문을 유지한다. 실제 제품과 예시의 기능 차이는 README와 화면 문구에 명시한다.
